An engineering team is preparing a compact language model for an offline assistant that runs on an Arm server. The assistant reads long technical requests, extracts constraints, and then produces short answers. The deployment must use exactly four CPU cores, cannot use a GPU, and must preserve deterministic output for a fixed seed. The model weights use Q4_K quantization, while activations are packed as q8_K blocks during prompt processing. The team has already ruled out prompt caching, extra worker processes, smaller models, reduced context, and quality changes because those would make the comparison misleading. They need an implementation change in the native AArch64 execution path.

Profiling shows that prompt processing spends most of its CPU cycles in the Q4_K by q8_K matrix multiplication kernel. The host exposes Arm I8MM instructions and a 128-bit SVE vector length, so the runtime correctly selects the NEON/I8MM body instead of the specialized 256-bit SVE body. The current compiler fully unrolls the four column-pair iterations, repeatedly materializes scalar scale values, and emits a large function with substantial register pressure. A proposed source patch keeps scale values in NEON vectors, widens and pairs them once per subblock, and asks GCC to retain the compact column-pair loop. It also separates the unused SVE body so that it does not inflate the hot NEON function.

The evaluation must proceed in a strict order. First compare the native kernel against the generic reference over multiple block counts and random seeds. Then confirm that deterministic full-model output is byte-identical. Only after correctness passes should the team measure direct kernel latency and whole-model prompt throughput. Baseline and candidate must use the same executable, model file, prompt, core affinity, thread count, batch settings, flash-attention setting, and compiler flags; only the CPU shared library may change. Measurements should run in a reverse-balanced baseline, candidate, candidate, baseline order. Report whole-model prompt throughput as the primary result, decode throughput as a regression guard, and direct microbenchmark speed only as supporting mechanism evidence.

In two concise sentences, explain what the patch changes and why this evaluation is trustworthy.
